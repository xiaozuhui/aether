# Aether 计算基准测试报告

> 实测快照：2026-08-29。重新运行 `cargo bench` 可得到当前机器的数字。

| 项目 | 值 |
| --- | --- |
| 被测对象 | aether-azathoth 0.6.0（Rust 树遍历解释器） |
| 基准程序 | [compute_bench.rs](compute_bench.rs)，10 个场景，每场景附 Rust 镜像校验 |
| 机器 | Apple M2，8 核，24 GB |
| 系统 | macOS 26.2（Darwin 25.2.0） |
| 工具链 | rustc 1.97.1 (8bab26f4f 2026-07-14) |
| 编译配置 | release：`opt-level = 3`、`lto = true`、`codegen-units = 1` |
| 运行方式 | 同一二进制连续两次完整运行（R1/R2），scale = 1.0 |

## TL;DR

- 全部 10 个场景**结果校验通过**：每个场景的 DSL 输出都与独立实现的 Rust 镜像（LCG 复算、num-bigint 阶乘全串比对、闭式求和、逐条复写的 6 个薪酬公式）精确一致——跑出的数字同时是被证明正确的数字。
- 解释器基线：简单语句约 **0.3 µs/条**，带条件与赋值的循环体约 **2 µs/迭代**。
- 一次完整运行约 **5–6 秒**纯解释计算；冷解析吞吐约 **26–31 万程序/秒**（每程序 2 行）。

## 方法论

- **场景独立**：每个场景用独立 `Aether::new()` 引擎（`ExecutionLimits::unrestricted()`），同源重复求值命中 AST 缓存，度量纯解释执行；`parse_cold` 例外，每次生成唯一源码强制走 lexer→parser→缓存插入全链路。
- **校验即回归网**：第 0 次执行先校验，之后每次执行也都校验，失败立即以非零退出码结束。
- **计时口径**：中位/最小/p95 仅计 `engine.eval`（校验在计时区间外）；「总耗时」列含逐次校验与源码生成开销。
- **大栈线程**：基准在 64 MB 栈线程内执行，深递归场景不受主线程栈限制影响。
- **统计量选择**：两次运行的中位数波动 ±20%（受系统后台负载影响），而**最小值几乎不变**（多数场景 < 2%）——跨版本/跨机器对比请以最小值为准。

## 分场景明细

每操作成本按最小值折算。

### monte_carlo_pi — 蒙特卡洛 π
- **负载**：LCG 伪随机（乘数 75/增量 74/模 65537）生成 40000 个点，判定单位圆内落点；每迭代 6 条 Set + 2 个条件求值。
- **校验**：Rust 侧用完全相同的迷你 LCG 复算落点数，π 估计值误差 < 1e-12。
- **成本**：**1.8–2.2 µs/迭代**，折合简单语句约 **0.3 µs/条**（~300 万条/秒）。

### big_factorial — 1200! 大整数累乘
- **负载**：`While` 循环 1199 次大整数乘法，结果 3175 位十进制。
- **校验**：num-bigint `BigUint` 计算的 1200! **全串逐字符比对**。
- **成本**：**1.8 µs/次乘法**（操作数最大 3175 位）。
- **历史对比**：0.6.0 修复 `Ratio` 乘法内置 gcd 规约的 O(n²) 劣化后，实测 20000! 由约 30 s 降至约 0.65 s；回归测试 `tests/spec_numeric_precision.rs::big_integer_hot_loop_does_not_degrade_quadratically` 以 FACT(2000) < 5 s 锁定该修复。

### fraction_harmonic — H_300 分数精确累加
- **负载**：300 轮 `FRAC_ADD(H, FRAC_DIV(1, I))`，全程 `Ratio<BigInt>` 精确分数，最终分母达 129 位。
- **校验**：f64 镜像 `(1..=300).sum(1/i)`，误差 < 1e-9。
- **成本**：**14.7 µs/次分数加法**——gcd 规约是主要开销，与 big_factorial 的 1.8 µs/乘对照鲜明。

### tail_fib — 尾递归 FIB(70)
- **负载**：三参数尾递归斐波那契，70 次尾调用，结果 190392490709135（< 2⁵³，f64 精确）。
- **校验**：与硬编码精确值严格相等。
- **成本**：**1.6 µs/次调用**（含 If 条件、实参求值、环境切换）。

### deep_tail_sum — 20000 层深尾递归
- **负载**：`SUM(20000, 0)` 尾递归计数。
- **校验**：结果严格等于 19999。
- **成本**：**1.1 µs/层**，且原生栈深度恒定——与 tail_fib 的单次调用成本一致，证明尾调用被改写为循环（TCO）而非真递归。

### data_structures — 500 元素数组管道
- **负载**：`While` 内 500 次 `PUSH` 构建数组，再过 MAP/FILTER/REDUCE/SORT 四个内建管道。
- **校验**：Rust 镜像复算 min + sum + 计数严格相等。
- **成本**：**15.8 µs/元素**全管道。`PUSH` 的值语义意味着每次调用复制整个数组（O(n²) 累计复制约 12.5 万元素），是本场景的主要成本。

### string_build — 字符串增长循环
- **负载**：400 轮「拼接 1 个数字 + `STRSLICE` 截断到 200 字符」，最终 `LEN == 200`。
- **校验**：长度严格等于 200（验证字符语义下「拼 1 截 1」的稳定态）。
- **成本**：**3.8 µs/轮**（字符串稳定在 200 字符，字符语义切片需逐字符定位）。

### payroll_batch — 1000 人月度工资单
- **负载**：每人 1 次 DSL 函数调用 + 6 个 `CALC_*` 内建（加班费/津贴/应发/社保/应税/净薪），月薪随序号变化 50 档。
- **校验**：Rust 侧逐条复写全部 6 个公式（含 7 档年度累进税表），总额误差 < 1e-6。
- **成本**：**11.9 µs/人**。

### generator_squares — 生成器急切收集
- **负载**：`Generator SEQ(1, 5000)` 被 `For-In` 首次触发急切收集 5000 个 `Yield`，循环体逐元素求平方累加。
- **校验**：与闭式 n(n+1)(2n+1)/6 = 41679167500 严格相等。
- **成本**：**0.96 µs/元素**（含收集、迭代、平方与累加），急切收集未引入显著额外开销。

### parse_cold — 冷解析
- **负载**：20000 个**唯一**源码（`Set X k` + 表达式，k 递增），强制 lexer→parser→AST 缓存 LRU 淘汰，无缓存命中。
- **校验**：每个程序求值结果严格等于 3k。
- **成本**：中位 **3 µs/程序**（约 1.5 µs/行），26–31 万程序/秒。注：单次仅数 µs，已接近计时器分辨率，最小值列仅供参考。

## 关键发现

1. **解释器基线吞吐**：简单语句 ~0.3 µs/条、循环迭代 ~2 µs、函数调用 ~1.6 µs——三个口径互相印证，处于树遍历解释器的健康区间。
2. **0.6.0 大整数修复有效**：1200! 稳定 2.1 ms；修复前 O(n²) 劣化下 20000! 需 ~30 s，现在 ~0.65 s。
3. **TCO 真实生效**：20000 层尾递归 21 ms、栈深恒定，单位成本与普通尾调用一致。
4. **解析 vs 执行**：解析一个 2 行程序 3 µs，执行 40000 次循环 80 ms——计算密集脚本中解析可忽略；短脚本/REPL 交互场景则由解析主导（正是同源 AST 缓存的目标场景）。
5. **测量稳定性**：最小值跨运行波动 < 2%，中位数受后台负载影响 ±20%——回归监控请以最小值为准。

## 优化方向（观察，未实施）

- `PUSH` 值语义的 O(n²) 复制（data_structures 场景主要成本）→ 可在 `Rc` 独占时原地追加（写时复制）。
- `FRAC_ADD` 的 gcd 规约 14.7 µs/次 → 可引入 Lehmer GCD 或对大分母跳过规约。
- 字符语义的 `STRSLICE` 需逐字符扫描 → 可缓存字符边界索引。

## 复现

```sh
cargo bench                                          # 全量（约 5–6s 计算；首次 LTO 编译需数分钟）
AETHER_BENCH_SCALE=0.2 cargo bench                   # 快速冒烟（重复次数缩至 20%）
AETHER_BENCH_ONLY=fib cargo bench                    # 只跑名字含 fib 的场景
AETHER_BENCH_SCALE=10 AETHER_BENCH_ONLY=deep cargo bench  # 单场景深压测
```

校验失败会以非零退出码结束——CI 中可直接 `cargo bench` 作为语义回归门禁。
